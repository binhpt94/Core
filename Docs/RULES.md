# Architecture rules (ARCH001–ARCH095)

Every gate prints violations as one line: `ARCHxxx path:line message`, followed by links to the sections below.
**Read only the section you need.** Rules are code (`Assets/_Game/Architecture/Rules`, `Assets/_Game/Tests/Architecture`);
this file explains them. A test fails if a rule has no section here.

Where each kind of rule runs:

| Kind | Rules | Runs in | Cost |
|---|---|---|---|
| **Static** (text/asmdef/YAML) | most | Claude hook after each edit, pre-commit, `test-gate.sh check/run`, `dotnet test`, Unity Play Mode + build gates | ms |
| **Reflection** (compiled code) | 020, 022, 023, 060–062 | `dotnet test LogicTests`, Unity EditMode | seconds |
| **Unity** (SerializedObject) | 072 (+073 deep) | Unity import / Play Mode / build gates, EditMode tests | needs Editor |

Exceptions are never added to a rule. Restructure the code instead, or ask a code owner.

---

## Assemblies

## ARCH001
**Pure assembly must set `noEngineReferences: true`** (Core, Contracts, Logic).
Why: makes `using UnityEngine` a compile error, and keeps the code runnable in `dotnet test`. Fix: set it in the `.asmdef`.

## ARCH002
**Pure assemblies may reference only `Game.*` and vendors of tier `foundation`** in `ArchitecturePolicy.txt` (today: UniTask).
Other libraries would break `dotnet test` and couple logic to vendors. Fix: put the dependency behind an interface in Core/Contracts
and implement it in the Unity layer.

## ARCH003
**Reference asmdefs by name, not `GUID:`.** GUIDs are unreadable for humans/agents and hide renames.
Fix: asmdef inspector → uncheck *Use GUIDs*.

## ARCH004
**Assembly name follows its folder**: `Features/F/Logic` → `Game.F`, `Contracts` → `Game.F.Contracts`, `Unity` → `Game.F.Unity`,
`Editor` → `Game.F.Editor`, `Tests` → `Game.F.Tests`, `Editor/Tests` → `Game.F.Editor.Tests`. Asmdefs elsewhere in a feature are not allowed.

## ARCH005
**Contracts reference only `Game.Core`.** Contracts are the stable public surface; they must not drag implementation along.

## ARCH006
**Core/Logic/Contracts must not reference Unity-side assemblies** (`*.Unity`, `*.Editor`, `Game.Bootstrap`, `Unity.*`).

## ARCH007
**Cross-feature references target `Game.X.Contracts` only.** Fix: add what you need to X's Contracts (owner approves the API change, ARCH023).

## ARCH008
**Only Bootstrap and tests may reference another feature's Unity/Editor layer.** Features talk through Contracts; Bootstrap wires them.

## ARCH009
**No circular assembly references.** Fix: move the shared piece to Contracts or Core.

## ARCH010
**Every feature has `README.md` and, if it has Logic, a Tests assembly.**

## ARCH011
**`autoReferenced: false` everywhere; `overrideReferences`/`precompiledReferences` only in test assemblies.**
Auto-referenced assemblies leak into `Assembly-CSharp`; precompiled DLL references bypass the dependency graph.

## ARCH012
**Bootstrap must not reference feature Logic assemblies.** It wires features through their public Installer/Module in the Unity layer
(`MathQuizInstaller` → `MathQuizModule`). Logic is internal anyway (ARCH020).

## Access control

## ARCH020
**Logic types are `internal`.** Logic is visible only to the feature's own Unity layer and tests via
`[assembly: InternalsVisibleTo("Game.F.Unity")]` / `("Game.F.Tests")` in `Logic/AssemblyInfo.cs`.
Result: even if someone adds an illegal asmdef reference, other features *cannot compile* against Logic.
Public surface = `Contracts/` + the Installer/Module/asset entry in `Unity/`.
A public MonoBehaviour implementing an internal interface uses **explicit implementation** (`void IQuizView.ShowQuestion(...)`).

## ARCH021
**`InternalsVisibleTo` only to the same feature** (`Game.F.Unity`, `Game.F.Tests`, `Game.F.Editor`). Fix: expose a Contract instead.

## ARCH022
**No public mutable fields on public types.** Fix: property with private setter, or a method that keeps the invariant.
Allowed: `[Serializable]` DTOs named `*Data`.

## ARCH023
**Public API must match `PublicApi.txt`** (Core: `Core/Runtime/PublicApi.txt`; each Contracts folder: `Contracts/PublicApi.txt`).
The test writes the compiled API to `TestResults/api/*.received.txt` and prints the diff. Breaking a contract is a deliberate decision:
the baseline files are CODEOWNERS-protected and denied to the agent. Report the diff, don't update it yourself.

## Code shape

## ARCH030
**No `partial` types in hand-written code.** Partial splits a class across files, not responsibilities: all parts share private
state, so nothing is isolated or testable separately. Fix: extract a new type (service/presenter/view) and inject it.
Only generated code may be partial: under a `Generated/` folder **and** starting with `// <auto-generated>`.

## ARCH031
**Max 300 lines per runtime file** (tests excluded). Catches god-classes early (and the "split it with partial" workaround). Fix: split by responsibility.

## Hidden invocation (calls the compiler can't see)

## ARCH040
**No Unity string dispatch:** `SendMessage`, `SendMessageUpwards`, `BroadcastMessage`, `InvokeRepeating`,
`Invoke("..")`/`Invoke(nameof(..))`, `CancelInvoke("..")`, `StartCoroutine("..")`, `StopCoroutine("..")`.
Fix: call an interface method; notify with a typed C# event owned by a Lifetime; delays via `IDelay` + `Lifetime.Run`.

## ARCH041
**No reflection/dynamic invocation in game code:** `Type.GetType`, `Assembly.Load*`, `Activator.CreateInstance`,
`GetMethod/GetField/GetProperty/GetMember/GetEvent/InvokeMember`, `MethodInfo`, `dynamic`.
They bypass asmdef boundaries and break silently on rename. Fix: inject an interface. (Tests and the rule engine are exempt.)

## ARCH042
**No lookup by name/path:** `GameObject.Find*`, `transform.Find("..")`, `Resources.Load*`, `Shader.Find`, `AddComponent("..")`.
Fix: a serialized reference inside the prefab, or the feature's asset entry (`MathQuizAssets`).

## ARCH043
**No scene search or singletons outside Bootstrap:** `FindObjectOfType`, `FindFirstObjectByType`, `FindAnyObjectByType`,
`FindObjectsByType`, `static ... Instance`. They make initialisation order implicit. Fix: Bootstrap creates/finds it and passes it in.
(Core may expose stateless `Instance`s such as `NullGameLogger.Instance`.)

## ARCH044
**No Animator parameters by string.** Fix: `static readonly int WinHash = Animator.StringToHash("Win");` then `animator.SetTrigger(WinHash)`.

## Pure code

## ARCH050
**No `UnityEngine`/`UnityEditor` in Core/Contracts/Logic** (also enforced by the compiler through ARCH001).

## ARCH051
**No `System.Random`, `DateTime.Now/UtcNow`, `Guid.NewGuid` in Logic/Contracts.** Fix: inject `IRandom` (Core owns `SystemRandom`) or a clock.

## ARCH052
**Pure code never waits directly** (`UniTask.Delay`, `Task.Delay`, `Yield`, `NextFrame`, `Thread.Sleep`). Fix: inject `IDelay`.

## ARCH053
**`.Forget()` only inside `Core/Runtime/Lifetime.cs`.** Fix: `lifetime.Run(token => WorkAsync(token))`.

## ARCH054
**Namespace segments must not shadow Unity types** (`.Application .Unity .Editor .Random .Debug .Object .Input .Time .Screen`).
Fix: `UseCases`, `Presentation`, `Infrastructure`, `EditorTools`.

## ARCH055
**No `GetHashCode()` / `HashCode.Combine` in Core/Contracts/Logic.** String hashes are randomised per process on .NET
(measured: three runs, three different values for `"board".GetHashCode()`), and implementations differ between runtimes, so any
seed, sort key or "id" built from them breaks replays. Fix: seeds via `RandomStreams.Derive`/`For(stream, keys)`, state via `StateHashBuilder`.

## ARCH056
**No floating point in `Logic/Domain` and `Logic/Simulation`** (`float`, `double`, `decimal`, `Math.Sqrt/Pow/Round...`).
Float results may differ across CPUs/compilers (x87/SSE/ARM, IL2CPP) and accumulate; replays and cross-runtime tests would drift.
Fix: integers (positions in 1/1000 of the lane, speeds per tick, durations in ticks, percentages). Convert to floats in the
presenter (`UseCases`) or the view, which are allowed to be approximate.

## ARCH057
**MonoBehaviours must not reference `Game.*.Domain` or `Game.*.Simulation`.** The feature's Unity layer can see Logic
(InternalsVisibleTo), so this keeps views honest: they receive view models through `I<Feature>View` and raise input events;
they cannot read or mutate gameplay state, and can be destroyed/replaced at any time (`Rebind`). Installers and
ScriptableObjects (config) may use Domain.

## State & async

## ARCH060
**No mutable static state** (writable static fields/auto-properties, `static readonly` arrays/List/Dictionary). They survive replays and
Play Mode without domain reload. Escape hatch: `[AllowStatic("reason + reset strategy")]`.

## ARCH061
**No static events.** They accumulate listeners across replays. Fix: instance event on an object owned by a Lifetime.

## ARCH062
**No `async void` / `async UniTaskVoid`.** Fix: return `UniTask`, start it with `lifetime.Run`.

## Unity data ownership

## ARCH070
**No serialized config values on feature MonoBehaviours** (`[SerializeField]`/public `int float double bool string long ...`).
Why: once a prefab/scene is saved, the serialized value wins. Changing the C# initializer (`= 10` → `= 20`) silently does nothing
for existing instances, and the same value can be overridden per prefab, Variant and scene. Single source of truth:
gameplay config → the feature's ScriptableObject (`QuizConfigAsset`) → pure config (`ToConfig()`) → runtime state.
Purely visual numbers (animation duration, padding) may be marked `[VisualTuning]`.

## ARCH071
**ScriptableObjects expose no public mutable state** (no public fields, no public setters). Runtime writes would persist in the Editor
and across scenes. Fix: private `[SerializeField]` + getter / `ToConfig()`.

## ARCH072
**Every serialized object reference on a `Game.*` component is required**, unless the field has `[OptionalReference]`.
Checked by the Unity validator on import, before entering Play Mode (blocks it), before builds (fails them), and in EditMode tests.
Required-by-default means forgetting an attribute cannot hide a missing reference.

## ARCH073
**No missing scripts.** Static check: `m_Script: {fileID: 0}` in YAML, or a script GUID that no `.meta` knows (when `Library/PackageCache` exists).
The Unity validator also reports null components. Fix: remove the component or restore the script *with its .meta*.

## Assets

## ARCH080
**Cross-feature asset references must target `Features/X/Assets/Public/`.** Detected by scanning `guid:` in YAML against `.meta` files,
in milliseconds without Unity. Scenes and Bootstrap count as "outside" too. Fix: reference X's public asset entry (e.g. `MathQuizAssets`),
which points to X's private assets. To delete a feature: `./tools/test-gate.sh refs Assets/_Game/Features/X` must print nothing first.

## ARCH081
**Scenes may override only layout on prefab instances** (`m_Name m_IsActive m_RootOrder m_LocalPosition/Rotation/Scale m_AnchoredPosition
m_SizeDelta m_AnchorMin/Max m_Pivot`). Anything else is data and belongs to the prefab, its Variant, or the config asset.
Prefab Variants may override visuals freely (skins), since config can't live on MonoBehaviours (ARCH070).

## ARCH082
**Feature assets live in `Features/F/Assets/Private/`** (default) **or `Assets/Public/`** (may be referenced by others).
Code stays in `Logic/`, `Unity/`, `Editor/`, `Contracts/`. This makes "copy/replace/delete a feature" a folder operation.

## ARCH083
**No `Resources/` folders under `Assets/_Game`.** They load by string and ship everything in the build. Fix: serialized references via the
feature's asset entry; Addressables with typed `AssetReferenceT<T>` if you need streaming.

## ARCH084
**Asset Serialization = Force Text** (`ProjectSettings/EditorSettings.asset`: `m_SerializationMode: 2`) **and every asset has its `.meta`.**
Required for the GUID/override scans, readable diffs and merging. A YAML asset without `.meta` fails (fail-closed): its references are
UNKNOWN and teammates' clones would get new GUIDs. Keep *Visible Meta Files* (default) and commit every `.meta`.

## UI testability & dev tools

## ARCH100
**Static layout lives in the view's layout recipe (`Unity/Views/<V>/<V>Layout.cs`) or in the prefab, never in other code.**
Writes to `anchoredPosition`, `sizeDelta`, `offsetMin/Max`, `anchorMin/Max`, `pivot`, `padding`, `spacing`, `preferred/min/flexible
Width/Height`, `SetSizeWithCurrentAnchors`... are rejected in `Features/*/Unity/**` outside `*Layout.cs` under `Views/`.
Why: then "I moved something 2px" can only be a change of that view's recipe or prefab, so the test gate runs the layout
tests of **that view only** (no game boot, no other feature). Data-driven movement (a slime's x, a progress bar) is allowed on
lines ending with `// layout: dynamic`, and those lines may not contain constants (sizes and bands stay in the recipe):
`var m = rt.anchorMin; m.x = x; rt.anchorMin = m; // layout: dynamic`.

## ARCH101
**Every view has its folder, fixtures and view cases** (by convention, no manifest):
`Unity/Views/<V>/<V>.cs` (MonoBehaviour implementing `I*View`), `DevTools/Fixtures/<V>Fixtures.cs` (typed fixtures incl.
`"smoke"`/`FixtureTags.Smoke`), `Editor/Views/<V>Cases.cs` (`ViewCases<I*View>`: how to create the view). The layout gate
(`Game.Core.Editor.Tests`) and *Tools > Game > UI > View Preview* discover them automatically.
Fix: move the view into its folder; add the fixtures file (start with `smoke` = a scenario fixture) and the cases class.

## ARCH102
**Dev tools never reach a release build.** Assemblies in `Core/DevTools` and `Features/*/DevTools` must set
`"defineConstraints": ["UNITY_EDITOR || GAME_DEVTOOLS"]`; runtime assemblies may not reference them (only Editor, tests and
other dev tools). The build gate also fails a non-development build that defines `GAME_DEVTOOLS`.
Fix: move cheat/fixture code into the feature's `DevTools/`; reach it from `Editor/` or tests, never from `Unity/` or Bootstrap.

## Product plan

## ARCH110
**`plan/features.md` must parse and be consistent.** Unique `F-`/`R-` ids, known dependencies, no dependency cycles, every
active feature has `[modules: X]` naming real `Assets/_Game/Features/X` folders. The parser never guesses: a line it can't read
is an error with its line number. The plan belongs to the human (agents write proposals to `plan/inbox/`). Syntax: `docs/PLANNING.md`.

## ARCH111
**`[Covers("R-ID")]` must name a requirement in the plan.** Requirement status is computed from the tests that cover it, so a
typo would silently leave a requirement "untested". If the requirement was removed or renamed, update the test's `[Covers]`
(or propose the requirement in `plan/inbox/`).

## Art slots

## ARCH120
**An art binding (`ArtSlotAsset`, `slotId: X`) must name a slot declared in code, owned by the same feature.**
Gameplay and presentation meet at the slot id; a binding to a typo would silently show the graybox forever.
Fix: use the id from the feature's `*ArtSlots` catalog; keep the binding asset inside that feature's `Assets/`.

## ARCH121
**Art slot contracts are declared in `Features/F/Logic/Domain/<F>ArtSlots.cs`, with a unique id `F.Name`** (a string
literal or a same-file `const string`). One catalog per feature makes slots discoverable (art gate, roadmap, dashboard).

## Files

## ARCH130
**Every file lives in the known layout.** Repo root: `Assets`, `Packages`, `ProjectSettings`, `LogicTests`, `tools`, `docs`, `plan`,
dot-folders and the known root files. `Assets/`: `_Game/`, `ThirdParty/`, `Plugins/`, `StreamingAssets/`. `Assets/_Game/`: Architecture,
Bootstrap, Core (Runtime/DevTools/Unity/Editor/Tests), Features, Scenes, Tests. A feature: Contracts, Logic, Unity, Editor, DevTools, Tests,
Assets (Public/Private), README.md. There is no registry: the path IS the ownership, so moving a file needs no bookkeeping.
Fix: move the file where it belongs; temporary work goes to `.scratch/` (gitignored, outside Assets/, never imported).

## ARCH131
**No leftovers:** scenes outside `Assets/_Game/Scenes/`, Unity's default names ("New Scene", "Untitled", "GameObject"), `*.tmp/.bak/.orig/.rej`,
`* copy.*`, `*_old.*`, `* (1).*`. Test without scenes (EditMode stages), keep throwaway files in `.scratch/`.
Fix: delete it (`files clean --junk --yes` deletes it for you if an agent made it and nobody touched it since) or give it a real name.

## ARCH132
**Every asset reference resolves.** A YAML reference to a GUID whose `.meta` was deleted since the branch base (and that no current `.meta`
carries) is reported at the referencing line, with a diagnosis: if a file with the same content exists elsewhere it was **moved without its
.meta** (Unity gave it a new GUID) and the message prints the command that restores the old `.meta`; otherwise it was deleted and the
message prints the restore command. Only GUIDs that existed in this project are judged (no false positives for packages/built-ins).
Prevention: move/rename assets inside Unity (or `git mv` the file AND its `.meta`).

## System map, docs and third-party

## ARCH090
**Generated system-map docs must equal what the generator produces from source right now, and the generator must have
understood everything it read.** Files: `docs/architecture/overview.md` + one page per feature in `docs/architecture/features/`
(orphan pages of deleted features fail too). Generated by `./tools/test-gate.sh graph --write` or Unity *Tools > Game > Regenerate
System Map*, never edited by hand (denied to agents). The message lists changed lines (e.g. `+MathQuiz -->|uses| Ads_Contracts`),
so a stale map doubles as an "architecture changed" notice in review.
Fail-closed: a state-table row the generator cannot read (a helper call, a non-const trigger, a `Transition` created outside a
table) is an ARCH090 error, even right after `graph --write`. Supported rows: `new Transition<E>(E.A, Trigger, E.B)` and `new(E.A, Trigger, E.B)`
inside `IReadOnlyList<Transition<E>> X { get; } = new ...[] { ... }` (or a `Transition<E>[]` field); triggers are string
literals or `const string`s of the same file. A reflection test also compares every runtime table with the diagram.
**Documentation rule:** enforced by hooks, pre-commit, the gate and CI, but it never blocks Unity Play Mode, imports or builds
(Unity shows a warning and the regenerate menu instead).

## ARCH091
**Hand-written docs may only mention our code names and paths that exist.** Inline-code anchors are checked:
paths under `Assets/_Game/`, `tools/`, `docs/`, ... must exist (placeholders like `<F>`, `X`, `*` are skipped);
`Game.*` names must be a declared namespace/assembly (+ used members); `Type.Member` must exist when `Type` is ours.
External APIs (`Activator.CreateInstance`) and fenced code blocks are not checked. Fix: update the doc after a rename/delete,
or write future names without backticks. Documentation rule: never blocks Unity (see ARCH090).

## ARCH092
**Vendor DLLs must not be Auto Referenced** (`.dll.meta`: `isExplicitlyReferenced: 1`). Unity's default makes a DLL visible to
*every* assembly, so any feature could call the SDK and the asmdef boundary would mean nothing. Fix: select the DLL → Inspector →
uncheck *Auto Reference*; the adapter references it explicitly (`overrideReferences` + `precompiledReferences`, allowed only for adapters).

## ARCH093
**Third-party code is registered, pinned and unmodified.** Every `.cs/.dll/.asmdef/.asmref` outside `Assets/_Game` must belong to a
`vendor source=` folder in `ArchitecturePolicy.txt` whose `sha256` matches (no "quick fixes" in vendor code, no game code hidden in
`Assets/Plugins`). Locally the hash is cached per file (path, size, mtime) in `TestResults/vendor-hash-cache.txt`, so an
unchanged multi-GB SDK costs only file stats; CI (`CI=true`) and `GAME_ARCH_NO_CACHE=1` always hash the full content. UPM vendors are pinned by `package=` + `version=` against `Packages/manifest.json`.
Fix: never edit vendor files; to upgrade, a code owner updates the folder and records `./tools/test-gate.sh vendor-hash <folder>`.
Source plugins without an asmdef land in `Assembly-CSharp-firstpass`, which asmdefs cannot reference: give the vendor folder an asmdef/asmref.

## ARCH094
**Third-party usage follows its tier.** `foundation` (UniTask): everywhere. `presentation` (DOTween, TextMeshPro): Unity layers only,
never Logic/Contracts. `sdk` (ads, IAP, analytics, Firebase): **only its declared `adapter=` assembly** (and that feature's tests).
Unregistered third-party references fail. Fix: depend on the adapter feature's Contracts (e.g. `IAdsService`), never on the SDK.

## ARCH095
**Exceptions are first-party, scoped, explained and time-boxed:**
`exception rule=ARCHxxx assembly=Game.F.Unity owner=<who> expires=yyyy-mm-dd reason="<why + exit plan>"`.
One existing `Game.*` assembly (no paths/globs), a known rule, owner + reason, an expiry; expired exceptions fail;
policy rules (ARCH09x) cannot be excepted. Vendor code needs no exceptions (it isn't strictly scanned), only registration.
